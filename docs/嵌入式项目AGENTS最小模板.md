# 嵌入式项目 `AGENTS.md` 最小模板

将下面代码块中的内容复制到新项目根目录，并保存为 `AGENTS.md`。模板可以直接使用，不必在第一次打开项目前填写所有信息。

项目专属的构建命令、目录职责和硬件参数，应先由 AI 只读查找，再由工程师确认后写入。不要把 AI 推测写成项目规则。

```md
# 项目协作规则

## 开始工作前

- 先阅读 README、相关文档、构建配置、程序入口和已有测试。
- 第一次接触项目时先进行只读分析，不要立即修改文件。
- 先复述任务目标、允许范围、禁止事项和验收标准。
- 明确区分已确认事实、设计假设、未知项和资料冲突。
- 没有依据的硬件参数、协议行为和实时性结论必须标记为未知。

## 实现原则

- 一个阶段只完成边界明确的一组工作，不顺手实现后续功能。
- 架构设计前，优先验证可能推翻方案的高风险假设。
- 开始实现前明确允许修改的文件和验收标准。
- 只做满足当前目标所需的最小改动，保留现有代码风格。
- 工作区内安全、可回退的本地修改可以按已确认范围执行。
- 扩大范围、删除数据、外部写入或真实硬件动作前必须暂停确认。

## 构建与测试

- 优先从 README、脚本、CI 配置和工程文件中查找真实构建与测试命令。
- 不要猜测或虚构构建命令；无法确认时报告未知项。
- 修改后运行与改动范围相符的编译、静态检查和自动测试。
- 报告实际执行的命令和结果；未运行的检查不得写成已通过。
- 自动测试不能替代示波器、逻辑分析仪、抓包、掉电、长稳和真实设备验收。

## 嵌入式安全边界

- 未经工程师确认，不修改芯片型号、引脚、时钟树、链接脚本、电气参数或现场协议。
- 不自动烧录固件，不操作真实设备，不执行现场控制动作。
- 不自动使能真实电机，不解除急停或故障状态。
- 不提高电流、速度或 PWM 上限，不绕过限位、看门狗和通信超时保护。
- 急停解除后不得自动恢复运动。
- AI 可以编写仿真、测试工具和检查清单；真实动作必须由工程师确认并执行。

## 信息安全

- 不在仓库中保存 API Key、访问令牌、设备密码、私钥或客户敏感数据。
- 日志、测试数据和示例中不得泄露秘密或客户现场信息。

## 完成任务时

- 检查代码差异是否超出约定范围。
- 报告新增或修改的文件、实际测试结果、失败项和未验证项。
- 明确区分软件验证与仍需工程师完成的硬件验收。
- 重大架构结论、已确认状态和遗留风险应更新到项目文档中。

## 项目专属信息

以下内容只有在工程师确认后才能补充：

- 目标硬件和板卡版本：待确认
- 操作系统或 RTOS：待确认
- 工具链和构建命令：待确认
- 自动测试命令：待确认
- 允许修改的主要目录：待确认
- 禁止修改的目录或配置：待确认
- 性能、内存和实时性指标：待确认
- 真实硬件验收方法：待确认
```

## 第一次分析完成后怎样更新

让 AI 先提出补充建议，不要让它直接把推测写入 `AGENTS.md`：

```text
根据只读分析结果，请列出建议补充到 AGENTS.md“项目专属信息”中的内容。

只允许使用已有文件明确支持的内容，并注明来源。
把无法确认的项目保留为“待确认”，不要修改文件。
```

工程师确认后再发送：

```text
我已经确认以下项目事实：
- [硬件和板卡版本]
- [工具链和构建命令]
- [自动测试命令]
- [允许和禁止修改的目录]
- [硬件验收方法]

请只更新 AGENTS.md 的“项目专属信息”，不要修改其他文件。
```

模板应保持简短。协议全文、架构历史、当前缺陷列表和一次性任务要求不应全部塞入 `AGENTS.md`，而应分别保存在项目文档、状态记录和当前提示词中。
