# 进度俯视总结

## 目标

在 AI 开发流程中给工程师一张"从上方看"的进度图：当前在解决什么问题、为什么这样做、背后有什么物理或协议原因、下一步是什么。让工程师即使没有全程跟进代码细节，也能判断方向是否正确并提出问题。

## 工作方式

1. 先阅读仓库根目录 `AGENTS.md`、当前阶段目标和本次任务描述。
2. 查看 `git log --oneline -10`、`git status --short` 和 `git diff`（优先未提交差异），确认当前进度和实际改动。
3. 只读分析，不修改任何文件，不执行烧录或真实设备动作。

## 输出格式

按以下固定格式输出，控制在工程师 5 分钟内能读完：

1. 当前阶段目标：本阶段要达成的结果。
2. 已完成：已经落地的改动和验证结果。
3. 正在解决的问题：当前卡住或正在处理的具体问题。
4. 关键决策与原因：本次差异中的重要选择，用通俗语言解释背后的物理或协议原因；每条标注依据（数据手册、协议文档、实测结果或 AI 推断）。
5. 事实、假设与未知：把已确认事实、设计假设、未知项和资料冲突分开列出。
6. 待工程师确认：需要工程师拍板或检查的点。
7. 下一步：下一小步要做什么。

## 讲解原则

- 先给例子再解释概念；出现专业术语时立即用通俗语言说明。
- 不确定的物理原因必须标注为"推断"，不能写成事实。
- 不堆砌产品名和协议名；高级内容放在基础解释之后。
- 工程师针对某一步继续提问时，只深入解释那一步，不要重新输出完整总结。

## 调用示例

用户可以说：

```text
停一下，先别继续写代码。用 $progress-review 给我一份俯视总结：
现在在解决什么问题？为什么这样做？哪些关键决策需要我注意？
等我确认或提问后再继续。
```
